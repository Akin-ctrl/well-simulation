# ADR 0015: Restrict Live Control To Actuator-Like Variables

- Status: Accepted
- Date: 2026-05-31
- Implementation: Implemented for the synthetic model

## Context

The digital twin should support live control inputs, but process outcome variables should be generated by the model rather than edited directly.

## Options Considered

### Option A: Allow all model variables to be edited

- Pros: Flexible for experimentation.
- Cons: Unrealistic and unsafe; users could directly overwrite pressure or flow.

### Option B: Allow only actuator/control variables

- Pros: Realistic and safe; process outcomes emerge from the model.
- Cons: Less direct manipulation for demos.

### Option C: No live controls, scenarios only

- Pros: Safest.
- Cons: Twin remains passive and lacks operator feedback loop.

## Decision

Use **Option B: live control is limited to actuator-like variables**.

## Rationale

This keeps the twin realistic. Operators change controls; the process responds. Pressure, flow, temperature, and related values should be consequences of state and controls.

## Allowed Live Controls

- `choke_position`
- `pump_status`
- `master_valve_status`
- `wing_valve_status`
- `emergency_shutdown`

## Consequences

- Live control commands must be validated, authorized, and audited.
- Direct edits to process outcomes are not allowed.
- Emergency shutdown should override normal control behavior.

## Implementation on 2026-10-13

Milestone 8B exposes only choke position, pump state, master valve, wing valve,
and emergency shutdown through the live command API. Process outcomes remain
model outputs. Shutdown and reset each require their own command with no other
target. A shutdown must be reset before another control can change.

[ADR 0038](0038-live-control-command-lifecycle.md) records the draft,
confirmation, current-authority checks, audit, expiry, and restart behavior.
These controls affect only the synthetic model; no physical safety claim is made.
